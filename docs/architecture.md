# Architecture and design

Browser -> same-origin HTTP API -> validated Service -> approved model planner/tool -> deterministic weather or scenario engine -> evidence-backed result -> browser.

The application uses Python, Pydantic and SQLite. The HTTP server uses Python's standard library instead of the originally proposed FastAPI stack, reducing installation requirements for the local interview demo. Production serving/deployment is a separate extension. The server binds to loopback and exposes explicit routes only.

Live planning calls the OpenAI Responses API with one strict function schema derived from Intent. Every field is required (nullable where appropriate), unknown fields are rejected, and Python validates arguments again before execution. The model receives registered coordinates/IDs and prior intent; it cannot execute code or make up tool implementations. At most one plan is executed per message. OpenAI errors/refusals do not switch to the demo parser. OPENAI_MODEL and OPENAI_API_KEY are environment configuration. No key enters the browser or database.

Weather and network calculations are deterministic Python. Narratives are assembled from those results rather than generated by a second LLM; this keeps displayed numbers consistent with evidence. The provider adapter can be replaced without changing analytics. DemoPlanner is explicitly opt-in, limited and not AI.

SQLite stores registered locations and per-conversation context, including the most recent resolved intent, explanation and optional explicitly supplied network. It uses short-lived connections closed after each transaction. This first version does not retain a full user message transcript. Weather responses are request-keyed file caches with timestamps and integrity hashes. The full development conversation must be exported separately for submission.

The allocator runs a minimum-cost maximum-flow algorithm over eligible hub-demand links. It maximizes served divisible daily demand before minimizing distance. It respects capacities and service components, reroutes through residual paths, and breaks equal-cost choices in stable ID order. Weather replay maps actual daily snowfall to explicitly assumed capacity fractions/recovery; weather evidence and profile assumptions accompany the output.

Repository structure and commands are in README.md. Runtime databases, caches and credentials are excluded from version control. Verification includes numerical regression tests, strict-schema/provider mocks, conversation evaluation cases and headless browser checks. Live LLM compatibility remains to be verified with the user's chosen model and credentials.

Official structured function guidance: https://developers.openai.com/api/docs/guides/structured-outputs
